## 后端端口改为可在 appsettings.json 配置
- 需求：宝塔上改配置文件比改环境变量直观，端口要支持在 `appsettings.json` 里配。
- 实现：`server/HexFront.Api/appsettings.json` 根级加 `"Urls": "http://0.0.0.0:5018"`。
- **踩坑（框架优先级与直觉相反）**：ASP.NET Core 自带顺序是「配置文件 `Urls` > `ASPNETCORE_URLS`」，实测证实（设了 env 的随机端口，进程仍监听配置文件的 5018）。若直接上这个方案会有两个真实后果：宝塔 .NET 站点面板的端口字段不生效；部署模板里 `ASPNETCORE_URLS=http://127.0.0.1:5018`（本意是不让后端直连公网）被静默盖掉 → 后端退回监听 `0.0.0.0`。
  - 顺带澄清：`Kestrel:Endpoints` 的优先级**更高**（官方文档：Kestrel endpoint configuration overrides UseUrls, ASPNETCORE_URLS, and --urls），用它会连环境变量一起盖掉，更不可取。
  - 解法：`Program.cs` 显式接管 —— `builder.WebHost.UseUrls(Environment.GetEnvironmentVariable("ASPNETCORE_URLS"))`（仅当 env 非空时调用）。最终优先级：`--urls` 命令行 > `ASPNETCORE_URLS` env > appsettings.json `Urls` 键 > Kestrel 默认。
- 新增测试 `server/HexFront.Tests/src/Protocol/ListenAddressConfigTests.cs`：真起进程读 Kestrel 的 "Now listening on:" 日志，锁定两个边界——不设 env 时端口取自 appsettings.json（5018，非 Kestrel 默认 5000）、设 env 时 env 覆盖配置文件。2 个全过。

## 前端天地图 key 配置（15:15-15:35）

用户要求「webfront 项目要新增天地图的 key」。

### 关键背景（决定了方案）
天地图按**请求的 Referer（页面所在域名）**校验 token 白名单，而底图瓦片是**浏览器直接**向
`t0~t7.tianditu.gov.cn` 请求的（`GeoMapView.tsx` + `MapView.ts`）——
**后端自己并不请求天地图**，它只是把 key 随 `/api/scenarios` 的 `tiles.tk` 下发给前端。
所以后端那把 key 的白名单若不含前端域名，前端必然拿不到底图。
⇒ 前端必须能配**自己的** key（按前端域名注册白名单的那把）。

### 实现（双通道，前端 key 优先）
- 新增 `webfront/src/services/tianditu.ts`：`TIANDITU_ENV_TKS` / `TIANDITU_ENV_TK` /
  `resolveTiandituTk(serverTk)`。优先级 **前端 env > 后端下发**。
- 新增 `webfront/src/vite-env.d.ts`：显式声明 `VITE_API_BASE_URL` / `VITE_TIANDITU_TK`
  （只扩展 `ImportMetaEnv`，**不要重复声明 `ImportMeta`**——会与 `vite/client` 冲突）。
- `GeoMapView.tsx`：`useState` 初始值改为 `TIANDITU_ENV_TK`；loadMeta 失败时回退 env key
  （原来后端不可达就彻底没底图了）。
- `HexMap.tsx`：`const tk = resolveTiandituTk(meta?.tiles?.tk)`。
- 新增 `webfront/.env.example`（通用模板）；更新 `.env.production.example`；
  同步 `deploy/release/.env.production.example`。
- `deploy/build-release-zip.sh`：新增 `VITE_TIANDITU_TK` 注入。
  **为空时不传该变量**（直接传空串会覆盖 .env.production 里的值，
  导致前端既没 key 也不回退后端）。
- `.gitignore`：新增 `.env`、`.env.development`、`*.db-shm`、`*.db-wal`
  （app.db 的 WAL/SHM 原本被跟踪了，是误提交）。
