## TIF 提取工具（已完成，无 GDAL）
- 需求：把 TIF（GeoTIFF DEM / landcover）提取成 C# 能直读的格式，作为工具开发；**明确不使用 GDAL/rasterio**。
- 方案：纯 Python `tifffile` + `numpy`（pip 可装、无原生 GDAL 依赖）。`tifffile` 仅用于解析 GeoTIFF 地理参考标签；像素解码对「256×256 瓦片 + DEFLATE + predictor 2」做了**手写解码**（`GeoBand._decode_block`，zlib 解压 + 水平差分还原），已与 tifffile 原生解码逐字节校验一致。
- 交付物：
  - `server/tools/gis/extract_terrain.py`：region（小区域）/ global（全球按 10°×10° 切瓦片）两种模式，输出 `.ter` 二进制 + `terrain_manifest.json`。每块含 int16 高程 + 可选 uint8 土地覆盖（土地覆盖按最邻近重采样到高程网格）。
  - `.ter` 格式：固定 80 字节小端头（magic TER1/version/crs/bbox/cols/rows/res/hasLandcover/elevNoData/lcNoData）+ int16 高程数组 + uint8 土地覆盖数组。坐标换算 `col=floor((lon-west)/resLon)`、`row=floor((north-lat)/resLat)`。
  - C# 读取器 `server/HexFront.Api/src/Services/TerrainTileReader.cs`：`TerrainTile.Load(path)` + `TrySample(lat,lon,out elev,out lc)` + `Contains`。
  - 文档 `server/tools/gis/README.md`。

## 后端端口改为可在 appsettings.json 配置
- 需求：宝塔上改配置文件比改环境变量直观，端口要支持在 `appsettings.json` 里配。
- 实现：`server/HexFront.Api/appsettings.json` 根级加 `"Urls": "http://0.0.0.0:5018"`。
- **踩坑（框架优先级与直觉相反）**：ASP.NET Core 自带顺序是「配置文件 `Urls` > `ASPNETCORE_URLS`」，实测证实（设了 env 的随机端口，进程仍监听配置文件的 5018）。若直接上这个方案会有两个真实后果：宝塔 .NET 站点面板的端口字段不生效；部署模板里 `ASPNETCORE_URLS=http://127.0.0.1:5018`（本意是不让后端直连公网）被静默盖掉 → 后端退回监听 `0.0.0.0`。
  - 顺带澄清：`Kestrel:Endpoints` 的优先级**更高**（官方文档：Kestrel endpoint configuration overrides UseUrls, ASPNETCORE_URLS, and --urls），用它会连环境变量一起盖掉，更不可取。
  - 解法：`Program.cs` 显式接管 —— `builder.WebHost.UseUrls(Environment.GetEnvironmentVariable("ASPNETCORE_URLS"))`（仅当 env 非空时调用）。最终优先级：`--urls` 命令行 > `ASPNETCORE_URLS` env > appsettings.json `Urls` 键 > Kestrel 默认。
- 新增测试 `server/HexFront.Tests/src/Protocol/ListenAddressConfigTests.cs`：真起进程读 Kestrel 的 "Now listening on:" 日志，锁定两个边界——不设 env 时端口取自 appsettings.json（5018，非 Kestrel 默认 5000）、设 env 时 env 覆盖配置文件。2 个全过。
- 全量测试 **271 通过 / 12 失败 / 共 283**（12 个仍是既有引擎/GDAL 产物问题）。`ApiFixture` 用 `--urls` 启动仍正常 → 命令行优先级未被 `UseUrls` 抢走。
